## Project Overview

**LeakCert** is a Python research framework implementing "Extraction-Resistant Code Completion with Information Leakage Certificates." It studies how language models memorize sensitive data (canaries), formally bounds extractable information using mutual information theory, and defends against extraction attacks via a runtime monitor.

## Architecture

The pipeline flows: **canary injection → fine-tuning → KL estimation → certificate → attacks → runtime monitor → evaluation**.

### Core Modules

**`leakcert/canary/`** — Generates CanaryType T1–T4 secrets (literal, paraphrase, semantic, vulnerability) and injects them into the fine-tuning corpus exactly once via `CorpusInjector`.

**`leakcert/model/`** — `BackendCompletionService` wraps a HuggingFace causal LM. `fine_tuner.py` trains with standard SGD or DP-SGD (Opacus). `CompletionService` is the abstract interface used throughout.

**`leakcert/certificate/`** — Implements five theorems bounding extractable information in nats (natural log units). `KLEstimator` computes per-canary D_KL(p_target ∥ p_ref) via likelihood-ratio, self-ratio, or MIA-classifier methods. Theorems 5/7 give query-budget bounds; 10/13 give concentration bounds; 17 gives extraction-probability bounds via Fano.

**`leakcert/runtime/`** — Four sequential components forming the online monitor (Figure 1): (1) certificate-budget throttle, (2) per-API-key rate limiter, (3) uncertainty-refusal classifier φ_u, (4) regex+hash target-string suppression. Emits one of: `emit | throttle | refuse | suppress`.

**`leakcert/attacks/`** — Five attacker strategies all targeting a `CompletionService`: A-fixed (static templates), A-grid (grid search), A-adaptive (UCB bandit, main attack), A-greedy-LRT (likelihood-ratio ranking), A-Carlini (gradient-free). All return `AttackResult`.

**`leakcert/defenses/`** — Six baselines B1–B6 wrapping a `DefenseWrapper` ABC: no defense, temperature, top-p, rate limit, content filter, and full LeakCert (B6).

**`leakcert/evaluation/`** — Five workloads W1–W5 and eight standardized scenarios E1–E8 defined as dataclasses. `ExperimentConfig` in `runner.py` orchestrates attack/defense combinations; results are written as JSON+CSV to `results/`.

### Extending the Framework

- **New attack**: subclass `Attacker`, implement `attack_canary()`
- **New defense**: subclass `DefenseWrapper`, implement `complete()`
- **New workload**: subclass `Workload`, implement `samples()`
- **New scenario**: add dataclass to `e_scenarios.py`, register in `runner.py`

### Server Deployment

Full GPU experiments use `server_deploy/`: `run_preflight.sh` → `setup_server.sh` → `make_data_bundle.py` (packages local artifacts) → `install_data_bundle.py` (extracts on server) → `run_server_evaluations.sh [smoke|small|full]`.

### Results

`Updated-Res/` contains sanitized results. Experiments use 5 seeds `[42, 137, 271, 314, 999]` with 500K-sample bootstrap confidence bounds. Paper tables are generated by post-processing scripts in `scripts/`.
